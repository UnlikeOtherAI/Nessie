## Verified As Stated

- **Finding 1 (protected grants dead-end):** Confirmed. The blueprint prompt (`packages/team-admin/src/global-agent-blueprints.ts:174-187`) tells Designer to send people to the Tools tab; the catalogue marks these `explicit_grant` (`packages/team-admin/src/agent-tool-catalog.ts:168-186`); generic updates reject protected keys via `mergeGenericAgentToolPolicy` → `assertGenericAgentToolPolicyInput` (`packages/team-admin/src/agent-update.ts:202-207`, `packages/team-admin/src/agent-tool-policy-core.ts:75-85`). Designer's `agent_update` goes through exactly this gate (`worker/src/run/pa-tools/agent-config.ts:150-300`).
- **Finding 2 (`tool_spec` misclassified):** Confirmed end-to-end. `tool_spec` is folded into `externalToolNames` via `builtinMetaNames` (`worker/src/run/execute/agent-loop.ts:127-132`), and `blocksPrivateConversationWrite` treats `isExternal` as an arbitrary third-party side effect (`worker/src/run/execute/private-conversation-write-gate.ts:36-43`), firing for shared agents — global agents are `agentKind: 'shared'` (`packages/team-admin/src/global-agent-bootstrap.ts:32`). The malformed `card_post` is the expected downstream symptom of schema discovery being denied.
- **Finding 3 (2,048 cap):** Confirmed. `maxTokens` default is 2048 (`packages/config/src/config-schema.ts:79`); `resolveAdvertisedOutputTokens` takes the min of configured/static/ledger caps (`worker/src/run/execute/run-inference.ts:45-54`); the no-tools recovery re-enters admission and reuses the same `requestedOutputTokens` (`worker/src/run/agentic-loop.ts:385-389`).
- **Finding 4 (false token limit):** Confirmed. `agentic-loop.ts:425` maps terminal `length` to `stop('tokens')` unconditionally; `classifyBudgetStop` renders "its token limit (107,323 tokens)" (`worker/src/run/execute/budget-stop.ts:68-99`). The backstop is 500,000 tokens (`worker/src/run/run-budget.ts:19-25`), so 107,323 was far from exhausted — the message was false.
- **Finding 5 (continuation strips identity):** Confirmed precisely. `shouldAutoContinue` excludes interactive runs (`worker/src/run/execute/continuation.ts:26-33`); the enqueue stamps `interactive: false` (continuation.ts:111); and `resolveDelegatedRequesterUserId` returns null unless `interactive === true` (`worker/src/run/delegated-identity.ts:121-131`), which is what strips Designer's identity tools — not merely the exclusion itself.

## Corrections Terra Needs (priority order)

- **P0 — Don't remove `tool_spec` from `externalToolNames`.** That set does double duty: it also skips the registry/grant gate (`worker/src/run/execute/tool-authorization.ts:240`). `tool_spec` is not in `BUILTIN_TOOL_DEFINITIONS`, so removing it would flip the denial to `tool_not_granted` for *every* run. The correct repair is a separate worker-meta classification: keep it in `externalToolNames` for the registry gate, but exempt it from the `isExternal` arm of `blocksPrivateConversationWrite`. The sub-agent arm builds its own `externalToolNames` with the same meta names (`worker/src/run/execute/agent-loop.ts:262-266`) — fix both. Tests must lock that `tool_spec` output stays filtered to allowed tools (`executeBuiltinToolSpec` already does this) while content sinks (`kb_*`, browser, email, MCP/executor) remain gated.
- **P0 — Don't fix continuation identity by stamping `interactive: true`.** That single boolean also controls `shouldAutoContinue` for the next generation (would break the bounded chain), wind-down chat handover vs silent auto-continue (`worker/src/run/execute/agent-loop.ts:95-98`), the budget-gate exemption, and the email-send approval hook (agent-loop.ts:181). Thread a dedicated structural field through `RunExecuteJobPayload` carrying the delegated requester, and re-admit identity tools at run-setup after fresh DB revalidation (run-setup already re-resolves per execution — keep that property; it satisfies the plan's "revalidate live access"). Note `withActionContext` already preserves actor/effectiveUserId/uoaIdentity (`packages/schemas/src/access-context.ts:98-104`) and the enqueue preserves `replyPlacement`/`principalUserId`/`triggerMessageId`, so identity retention is mostly plumbing the admission condition, not the context.
- **P0 — Raise only the main-turn output allocation, never the shared config default.** Utility calls fall back to the same `runtimeModelConfig.maxTokens` (`worker/src/run/execute/run-inference.ts:377-390`); a global raise would silently inflate every utility/compaction/checkpoint-note call. Make the raise reasoning-aware at `resolveAdvertisedOutputTokens`/`mainOutputTokens`, and coordinate with the existing compose raise (`resolveMainOutputTokens` + `resolveComposeOutputTokens`) so the two don't multiply. Keep the recovery budget persistent across checkpoints — `restoreOutputFinalizationState` (`worker/src/run/output-finalization.ts:30-44`) currently does this and adaptive recovery must integrate with that state machine, not bypass it.
- **P1 — The false-`tokens` classification fix has a fixed blast radius.** Touch points: `BudgetExhaustionReason` (`worker/src/run/agentic-loop-types.ts`), `agentic-loop.ts:425`, `REASON_TO_STOP`/`RunStopReason`/`stopPhrase` (`worker/src/run/execute/budget-stop.ts:26-99`), checkpoint reason, events, continuation metadata, and the admin stop surface. Existing tests pin the wrong behavior and must be updated, not deleted: `worker/src/run/execute/budget-stop.test.ts:25` and the length-finalization cases in `worker/src/run/agentic-loop.test.ts`.
- **P1 — Protected-grant reuse target is API-only today; move, don't reimplement.** The single door is `setAgentToolPolicyForRegistryEntry` + `requireExplicitEntry` + `runWithDeepWaterTransitionLock` + `synchronizeMcpAgentGrant` + `translateActiveRunError` (`api/src/services/agent-tool-policy-registry.ts:358-377`), reached from `PATCH /api/mcp/tools/:toolRegistryEntryId/policy-targets/:agentId` with `requireOwner` (`api/src/routes/mcp/tools.ts:276-330`). Per the reuse rule and `docs/standards/personal-assistant-tools.md`, Terra must move this into a shared package (`@nessie/team-admin` already hosts `agent-tool-policy-core.ts`) and keep the route and the new Designer tool on one implementation. Two parity obligations the plan should name explicitly: policy keys differ by handlerKind (builtin → `toolId`, MCP → entry uuid, `registryEntryPolicyKey`), and the route publishes `agent.updated` realtime events plus maintains the audit trail — the worker path must emit both.
- **P1 — Authorization is owner-only, and the plan's own test list agrees.** The route is `requireOwner`; plan item 6 expects non-owner denial. So the new conversational grant must check the *requesting member's* fresh org-owner role (the `resolveActingMember` pattern in `agent-config.ts`), never Designer's system identity — "acting with the requesting person's authority" means owners finish in chat and non-owners get a truthful refusal, which keeps the blueprint's "owner-granted" framing accurate after rewording.
- **P2 — Surface-completeness gaps beyond protected grants the audit should name:** Designer has `agent_trigger_create` but no trigger list/update/delete (API: `GET /api/agents/:agentId/triggers`, `api/src/routes/triggers.ts:48`); `agent_bind_channel` but no unbind (admin uses `DELETE` on bindings, `admin/src/facades/agents/mutations.ts:158`); no agent delete. Config/model/provider/subscription/limits/ownership/todos/core are already covered by `agent_update`.
- **P2 — Pin the truncated-batch behavior with a test.** The recovery branch drops tool calls from a length-terminated completion (`agentic-loop.ts:408-416` pushes the assistant message without `toolCalls`). That is the correct "never execute incomplete tool calls" semantics, but today the batch is silently discarded — lock it in, and rely on `toolRecorder`/`claimCheckpointForRun` (`continuation.ts:96-99`) tests for the no-replay guarantee.
